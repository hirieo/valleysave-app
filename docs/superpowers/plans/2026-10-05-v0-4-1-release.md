# ValleySave v0.4.1 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publicar una versión parcheada de ValleySave con el código actual, los paquetes Windows y Android, y una nota transparente sobre la compatibilidad con partidas modificadas mediante SMAPI.

**Architecture:** El código ya está integrado en `licendev` y `main`; el único cambio de producto será el aumento de versión. Los binarios se compilarán desde ese mismo commit, se verificarán, se empaquetarán con todas sus dependencias y se adjuntarán a una release nueva de GitHub.

**Tech Stack:** Flutter/Dart, CMake para Windows, Gradle para Android, Git/GitHub CLI.

---

### Task 1: Aumentar la versión de publicación

**Files:**
- Modify: `pubspec.yaml:4`

- [ ] **Step 1: Cambiar la versión a `0.4.1+35`**

```yaml
version: 0.4.1+35
```

- [ ] **Step 2: Confirmar que solo se modifica la versión**

Run: `git diff -- pubspec.yaml`

Expected: una línea cambia de `version: 0.4.0+34` a `version: 0.4.1+35`.

### Task 2: Compilar y verificar los artefactos de publicación

**Files:**
- Create: `build/app/outputs/flutter-apk/app-release.apk`
- Create: `build/windows/x64/runner/Release/valleysave.exe`

- [ ] **Step 1: Compilar el APK firmado**

Run: `flutter build apk --release` con `KEY_PASSWORD` cargada únicamente desde `android/keystore_password.txt`.

Expected: `Built build\\app\\outputs\\flutter-apk\\app-release.apk`.

- [ ] **Step 2: Verificar la firma del APK**

Run: `apksigner verify --verbose --print-certs build\\app\\outputs\\flutter-apk\\app-release.apk`

Expected: verificación v2 correcta y certificado SHA-1 `ec9de27e713e4221c0d46c6e6e9047d771fef6ef`.

- [ ] **Step 3: Compilar Windows Release**

Run: `flutter build windows --release`

Expected: `build\\windows\\x64\\runner\\Release\\valleysave.exe` con una fecha de modificación de hoy.

- [ ] **Step 4: Empaquetar Windows completo**

Run: `Compress-Archive` sobre el contenido de `build\\windows\\x64\\runner\\Release`.

Expected: ZIP que incluye `valleysave.exe`, DLLs y el directorio `data`.

### Task 3: Publicar código y release de GitHub

**Files:**
- Modify: `pubspec.yaml:4`
- Create: Git tag `v0.4.1`
- Create: GitHub release `v0.4.1`

- [ ] **Step 1: Restaurar cambios automáticos de Flutter ajenos a la release**

Run: `git status --short`

Expected: solo `pubspec.yaml` y este plan, además de los artefactos ignorados bajo `build/`.

- [ ] **Step 2: Confirmar, integrar y subir la versión**

Run: `git add pubspec.yaml docs/superpowers/plans/2026-10-05-v0-4-1-release.md && git commit -m "chore: bump version to 0.4.1+35"`.

Expected: el mismo commit queda publicado en `licendev` y `main`.

- [ ] **Step 3: Crear la release con artefactos Windows y Android**

Run: `gh release create v0.4.1` con el commit de `main`, el APK, el ZIP Windows y una nota que indique que la compatibilidad con partidas que usan mods mediante SMAPI está en desarrollo.

Expected: release pública con ambos artefactos descargables; no promete compatibilidad total con todos los mods.
